# Security

This repository is public so that a question with real money behind it —
**"could MirrorStack break our website?"** — can be settled by reading code
rather than by trusting a support reply. That only works if the claims in it are
checkable, and if there is somewhere to go when one of them turns out to be
wrong.

## Reporting

**Email `security@mirrorstack.ai`.** Please do not open a public issue for a
vulnerability.

Include whatever you have: the file and line, what you think it lets someone do,
and a sequence that demonstrates it. A minimised fuzz input or a mutation that
survives the test suite is a perfectly good report — see
[`docs/MUTATION.md`](docs/MUTATION.md) for how we run those ourselves.

We will acknowledge within three working days and tell you what we think of it
within ten. If we disagree with you we will say why, in enough detail that you
can argue back.

**There is no bounty programme.** We would rather say that plainly than imply
one.

## What is in scope

Anything that breaks a claim this repository makes. The claims are enumerated in
[`README.md`](README.md) and [`docs/DESIGN.md`](docs/DESIGN.md); the shortest
form of them is:

- A record can only be written at or under an anchor the customer proved.
- The caller cannot choose a record's value.
- The ownership proof is the customer's to publish, and deleting it stops
  every write.
- A sealed envelope cannot be moved between rows, replayed into more authority,
  or forged by the caller.
- There is no delete, anywhere.

A demonstration that any of those is false is the most useful thing you could
send us.

Also in scope: a **comment or document that overstates what the code does**. In
a repository whose purpose is to be read, a confident false sentence is a defect
of the same class as a bug, and we treat it as one.

## What is out of scope

- **The deployed service's network surface.** It is not behind API Gateway and
  has no public route; it is invoked by IAM-gated `lambda.Invoke`. Scanning it
  tests a threat model this repository is not about — see
  [`docs/THREAT-MODEL.md`](docs/THREAT-MODEL.md).
- **MirrorStack's private half.** It is not published, and the whole point of
  this repository is that you should not have to trust it. If you find something
  in *this* code that depends on the private half behaving, that IS in scope —
  that is the interesting case.
- Reports generated by a scanner with no demonstrated impact.

## Known open issues

We would rather you spend your time on something we have not already found.
These are open **right now**, stated at the top of the README and in
[`docs/DESIGN.md`](docs/DESIGN.md)'s status block:

| | |
|---|---|
| The legacy `publish(records)` action is still routed | It takes both the record list **and the anchor** as request fields. It is not bounded by the connected domain — its reach is the whole zone the provider authorized. Retiring it is the next change, caller first. |
| `verify()` trusts a recursive resolver | Whoever can spoof a DNS answer to us can forge an ownership proof. Certificate authorities solve this with multi-perspective validation and DNSSEC; we do not yet. |
| The rate floor is declared, not enforced | Nothing here slows a caller that advances a registration in a loop. |
| Lane 2 cannot be authorized | Nothing in the deployed binary mints a consent acknowledgement, so it refuses. Fail-closed. |

Finding a *new* way to exploit one of these is still worth reporting. Telling us
one of them exists is not, and we are listing them here so nobody wastes an
afternoon.

## Cryptography

Report anything, but the following are deliberate rather than oversights, and
the reasoning is in the code at each site:

- The ownership proof accepts a value under **any** key in the keyset, not only
  the active one. Rotation must not break a proof a customer published months
  ago and has no reason to revisit.
- Sealed envelopes are **replay-safe rather than replay-proof**. A stateless
  service cannot count, and a counter inside a sealed envelope is rollback-able
  in the direction that grants more authority. Rolling one back grants no
  authority it did not already carry.
- The consent acknowledgement is scoped to one **registration**, not to one
  authorization attempt, for the same reason.
